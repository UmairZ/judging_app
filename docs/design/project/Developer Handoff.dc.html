Iconography & motif

The only decorative motif is the brass diamond (a 45°-rotated square) and thin rule, drawn from the logo's gold dots. Use sparingly as section dividers and accents. UI icons: a simple line set (Lucide/Phosphor) at 1.5px stroke; functional glyphs already in use — + − ↻ ⚠ 🔒. Do not introduce illustrative or filled icon styles.

Interaction & behavior notes

The behaviors a static mock can't show — this is where builds drift from intent. Read alongside spec §3, §5, §9.
•
Running score recomputes locally on every tap
No spinner, ever, for grading. The shared scoring module runs on-device; raw deduction events sync as the source of truth. Score = 70·H + 25·T + 5·V recomputed each render.
•
Steppers, not undo
Each key is + / −. + appends a timestamped event to events[]; − pops the most recent of that type. Reset points clears the active question's marks, voice, and DQ flag. There is no global undo — correction is per-key.
⚠
Auto-flag DQ prompt — the single knob
When a question's hifz_deduction reaches hifz_base (hifz hits 0), show the “Call it?” prompt. Confirm → question DQ'd (hifz and tajweed = 0). Dismiss → keep it, tajweed still counts, and set a dismissed flag so it never re-prompts. Never DQ silently.
•
Voice & style is per-question
Rated 0–5 on each question, alongside the deduction keys. V = mean(voice/voice_max) over rated questions only; unrated questions don't drag it to 0 (shown as “pending”).
•
Lazy session creation & completeness
A sessions doc only exists after the judge's first input — its absence is “not started.” Completeness = started sessions / panel size (e.g. “2 / 3”); distinguish in progress from finalized so admin knows if a partial score is still moving.
•
Offline-first & never final
Write local first (“Saved locally”), sync when online. Per-judge document ownership → last-write-wins, no conflicts. Sessions are always editable; reopening recomputes from the raw event log.
•
Tie-break order
Sort by score → H̄ → T̄ → total prompted_failed (asc) → then sudden-death question (panel-averaged, placement only) or manual override with an audit note.

Scoring engine reference

# per session, score in [0,100]
session = 70·H + 25·T + 5·V
# per question q
hifz_q = dq ? 0 : max(0, 10 − ded_h)
taj_q  = dq ? 0 : max(0, 10 − ded_t)
# component = mean of fractions
H = mean(hifz_q / 10)
T = mean(taj_q / 10)
V = mean(voice / 5)  rated q only
Default config (live-editable)
Weights H / T / V70 / 25 / 5
hifz_base10
tajweed_base10
voice_max5
prompted_fixed / failed1 / 2
tajweed major / minor1 / 0.5
self_corrected0
One module, two consumers. Ship scoring as a single pure TypeScript module imported by both the judge app (live score) and admin (leaderboard). Nothing scoring-related is hardcoded — all knobs live in config/scoring; scores recompute at read time. hifz_base is the single spread knob and the DQ auto-flag trigger.

Screen inventory & dev notes

1Live grading judgeCenterpiece. Local scoring, steppers, per-q voice, auto-flag, reset, add-question. Offline-safe, no spinners.
2Welcome + queue judgeNo login. Queue status derived from session docs; photos cached for offline.
3Review & edit judgeReopen any graded session; recompute from events. Nothing is locked.
4Leaderboard + tie-break adminPer category×division. Completeness, spread flags, tie resolution. Online-preferred. CSV/print export.
5Registrations + promote adminImmutable master; promote → contestant + enrollment(s). Unmapped categories surfaced, never dropped.
6Scoring & panels config adminLive weight sliders (block save unless = 100). Panels×slots grid; a panel can cover many slots.
7Structure editor adminDivisions master + per-category min-questions & enabled divisions. Slots regenerate automatically.
8Contestant management adminEdit fields, photo, enrollments, active. Division lives per enrollment, not per person.
9Admin sign-in + unlock adminOne credential. On judge laptops, logo long-press → password prompt. Admin never resident on a judge device.
10Device provisioning adminPick judge for seat → mint judge-scoped token (persists, offline) → land on welcome. Same flow for swaps.
11Projector leaderboard displayRead-only, big-type, auto-cycles categories. Renders whatever has synced.
All eleven are in the companion file Ibn Katheer Judging.dc.html. The live grading screen there is fully interactive — tap the keys to validate scoring behavior against this reference.
